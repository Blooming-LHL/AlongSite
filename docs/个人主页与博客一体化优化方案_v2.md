# 个人主页与博客一体化优化方案 v2

状态：已按确认方案完成实现，本地验证通过；线上发布与服务器级重定向单独验证。\
适用项目：AlongSite（Hugo + Pagefind；Netlify 与个人服务器 Nginx 8081）。\
本次交付：方案及已确认部分的实现，详见第 12 节实施记录。

## 1. 结论

取消现有“个人简介 / 我的博客”二选一入口页，直接把英文个人简介作为网站首页。博客保留独立页面，通过个人简介中的 `My Blog` 模块进入。

两类页面共用浅色背景、紫色强调、柔和玻璃材质与交互规则，但不强行共用同一种布局：个人简介强调身份与经历，博客强调文章与阅读。

项目、技术能力、简历下载暂不展示具体内容，联系方式不填写、不输出。保留未来补充空间，不用虚构内容或大面积占位卡片填满页面。

## 2. 用户要求与本方案的解释

| 用户要求 | 本方案的处理 |
| --- | --- |
| 不要现有主页，直接进入个人简介 | `/` 直接渲染英文简介，而不是先显示入口卡片或跳转到另一个页面 |
| 博客作为个人主页中的跳转模块 | 简介首屏提供 `My Blog` 操作，并在页面内保留一个完整的博客入口模块 |
| 个人简介默认英文 | 首次访问 `/` 固定为英文；中文简介作为可选版本保留 |
| 项目、技术能力、简历下载暂时留白 | 保留精简的模块标题与布局位置，不展示现有条目、技术标签、架构图、成果或下载按钮 |
| 联系方式暂时不填 | 个人简介不显示邮箱、GitHub 联系入口、联系按钮、表单或虚假占位联系方式 |
| 协调个人简介与博客 UI | 统一颜色、字体、圆角、玻璃效果及导航反馈；保留各自适合的内容布局 |

以下是为推进方案作出的明确假设，不代表额外的用户要求：

- 保留目前已经确认的个人介绍、工作经历、教育背景和研究概况，不额外扩写履历，也不自行推断事实。
- “留白”理解为内容为空、保留低高度的章节位置，而不是保留一整屏空白或显示 `Coming soon`。
- 联系方式的留空范围默认是个人简介及其页头、页脚；不擅自删除博客既有联系方式。是否全站隐藏，实施前可单独调整。
- “默认英文”仅针对个人简介，不要求翻译博客文章，不引入全站自动语言识别或语言偏好存储。

## 3. 实施前的实现与问题

以下判断记录实施前的项目源码状态，而非仅依据截图。

### 3.1 访问路径多了一层选择

`themes/along/layouts/home.html` 目前负责二选一入口；实际简介位于 `/about/` 和 `/en/about/`。访问者必须先选一次，才能看到身份与经历，重复了顶部导航已经提供的功能。

### 3.2 两套视觉语言差异明显

- `static/css/portfolio.css`：暖白背景、朱红强调、小圆角、细线与偏编辑式排版。
- `static/css/main.css`、`home.css`：浅紫底、彩色渐变、玻璃面板与较大的圆角。
- 两类页面的强调色、背景、按钮及文字层级没有形成连续体验。

### 3.3 暂不展示的内容分散在多个位置

简介模板不仅输出项目与技能，还在首屏、顶部导航、页脚和联系区提供简历或联系入口。仅清空正文某个模块，仍可能留下按钮、空链接或其他入口。

现有 PDF 位于 `static/cv/`，另有 `/cv/zh/`、`/cv/en/` 打印页面。隐藏下载按钮并不等于这些地址不可访问，也不等于相关内容已从公开 Git 历史删除。

### 3.4 语言与测试仍以旧结构为前提

当前首页默认使用中文上下文；简介语言由 `profile_language` 控制。现有测试还明确要求旧英文地址、项目架构、简历下载等内容，不能只改模板而不更新对应验收条件。

## 4. 信息架构与路由

### 4.1 目标结构

```text
/                    英文个人简介，默认入口
├── /cn/about        中文个人简介，手动切换
└── /blog/           中文博客入口
    ├── /writing/    全部文章及既有文章地址
    ├── /categories/、/tags/
    ├── /now/
    └── /search/

/en/about/           旧英文地址，兼容跳转到 /
```

| 地址 | 调整策略 |
| --- | --- |
| `/` | 原地变为英文个人简介，返回正常内容页，不重定向 |
| `/cn/about` | 中文个人简介入口，内容结构与英文一致 |
| `/en/about/` | Netlify 与 Nginx 配置 301 到 `/`；本地静态预览提供兼容跳转页，避免旧链接失效 |
| `/blog/` | 保留博客首页及现有瀑布流 |
| 文章、分类、标签、搜索地址 | 保持不变，不迁移文章，不改 slug |
| `/cv/zh/`、`/cv/en/` 与 PDF | 暂不从简介提供入口；是否同时停止公开访问，见第 8 节的独立边界 |

不把 Hugo 整站的默认语言直接切成英文。优先沿用现有 `profile_language` 机制，让根首页使用英文上下文，避免影响中文博客与搜索。

### 4.2 导航与语言切换

- 英文简介顶部：身份标识、`My Blog`、`EN / 中文`。
- 顶部不设置独立的 `About` 导航项，也不出现“网站入口”或二选一首页入口。
- 中文简介提供对应中文导航；英文切换指向 `/`，中文切换指向 `/cn/about`。
- 博客导航中的“个人主页”指向 `/`，“我的博客”指向 `/blog/`，避免同时出现两个含义相同的首页入口。
- `My Blog` 使用普通链接、同标签页打开；博客提供清楚的返回个人主页入口。
- 语言切换不依赖 JavaScript，且不将“进入中文博客”误标为“切换简介语言”。

## 5. 个人简介页面设计

### 5.1 页面顺序

```text
顶部导航：身份标识 / My Blog / EN · 中文
│
├── Overview：头像与状态、身份、简短介绍、My Blog 操作
├── My Blog：独立入口模块，一句话说明 + Explore the blog
├── Experience：已确认的工作与实习经历
├── Education：已确认的教育背景与研究概况
├── Selected Work：仅保留标题，内容留空
├── Technical Skills：仅保留标题，内容留空
├── Résumé：仅保留标题，无下载按钮
└── 简洁页脚：版权 / 返回顶部
```

联系方式不设独立空白大区块，也不保留一个没有目的地的 `Contact` 导航。

### 5.2 首屏

- 用头像、状态标识与 `ALong / Henglong Liang` 建立身份，不再用一整屏“选择从哪一面了解我”的说明。
- 保留 `AI Engineer` 定位和已确认的简短介绍，英文优先。
- 主操作为 `My Blog`，次级操作可为 `Experience` 页内锚点。
- 移除 `View Work`、CV、Email 等指向暂不展示内容的操作。
- 头像继续使用现有资源和裁剪方式；状态标识表达个人状态，不伪装成实时在线指示器。
- 不用技能清单、技术徽章或项目成果来填补留白区域；职业名称和真实经历不因此被清除。

### 5.3 博客入口模块

建议文案（可在实施时微调）：

> **My Blog**\
> Notes on engineering, reading, and everyday life.\
> Explore the blog →

使用一张横向、低饱和度的玻璃卡片，文字与跳转操作清晰可见。不在简介内复制完整文章瀑布流，不新增接口，也不要求额外维护一套博客摘要数据。

卡片本身只有一个清楚的链接语义，避免整卡链接内部再嵌套按钮。首屏按钮与模块均指向 `/blog/`。

### 5.4 留白模块的具体表现

- `Selected Work`、`Technical Skills`、`Résumé` 仅保留标题、细分隔与少量垂直间距，不渲染现有明细。
- 不显示假项目、示例技术栈、灰色禁用下载按钮或 `#` 空链接。
- 不为留白模块设置固定的大高度，不为维持视觉完整而编写占位履历。
- 目录仅列出有实际内容的章节；空模块不进入顶部操作或章节导航。
- 后续由用户确认具体资料后，再恢复模块内容和相应入口；本轮不设计复杂 CMS、通用配置系统或自动发布个人履历的流程。

## 6. UI 协调方案：同一套材质，不同的信息密度

推荐方向：以现有博客的浅色玻璃风格为基础，降低个人简介的渐变强度，而不是把博客全部改成暖白朱红风格。

### 6.1 统一与保留

| 维度 | 共用规则 | 个人简介 | 博客与文章 |
| --- | --- | --- | --- |
| 颜色 | 深紫文字、紫色强调、浅色背景 | 大面积近白，背景渐变更淡 | 保留现有柔和彩色渐变 |
| 材质 | 细亮边、柔和阴影、低饱和玻璃效果 | 用于导航、概览和博客入口 | 用于导航、卡片、辅助面板 |
| 圆角 | 大面板约 24–32px，小控件约 12–16px | 克制使用，不把每段经历装入独立卡片 | 保留封面卡片的完整轮廓 |
| 字体 | 共用本地系统无衬线字体栈 | 英文标题清楚，正文舒展 | 中文阅读优先，长文不跟着放大 |
| 交互 | 相同的 hover、focus 与选中反馈 | 导航和博客模块 | 侧栏导航、标签、文章卡片 |
| 布局 | 相同间距尺度与对齐原则 | 居中简介与轻量章节索引 | 保留文章双列瀑布流和阅读布局 |

基础颜色优先复用 `main.css` 已有的 `--ink`、`--muted`、`--paper`、`--accent` 等变量，减少 `portfolio.css` 自成体系的覆盖。不为这次调整新建另一套主题引擎。

### 6.2 液态玻璃交互

- 可点击导航项 hover 或键盘 focus 时，显示相同的半透明圆角背景、细边与轻微阴影；当前页面的选中态持续可辨认。
- 博客入口 hover 时可以轻微上浮，正文及非交互标题不套用按钮反馈。
- 优先复用 CSS，不增加鼠标跟踪、WebGL 或重型动效库。
- 不支持背景模糊时使用足够不透明的浅色底；文字不能依赖模糊效果才看得清。
- 尊重减少动态效果的系统偏好，保留可见的键盘焦点；触屏操作不依赖 hover 才能发现入口。

### 6.3 宽度与响应式

- 个人简介主容器建议上限约 1200px；长段落控制在约 60–72 个英文字符的可读行宽，不强行占满屏幕。
- 博客的灵感区和双列卡片继续使用博客主区域的有效宽度，不继承简介正文的窄行宽限制。
- 桌面简介可使用轻量章节索引；窄屏改为普通文档流或换行导航，不能挤压正文。
- 手机端博客卡片保持单列，个人简介与博客模块都不产生页面级横向滚动。
- 文章正文继续使用现有高不透明度阅读面板，不为了统一视觉而降低长文对比度。

| `hugo.yaml`、博客导航相关局部模板 | 删除过时“网站入口”语义，区分个人主页和博客入口；不改文章 permalink |

明确不在本轮修改：

- `scripts/` 中的 front matter、知识库路径解析与发布同步逻辑。
- 私人 `Blog`、`Blog/Public`、`.publish-manifest.json` 及受管文章、图片。
- 现有封面识别、卡片瀑布流算法、每日寄语、正文排版和文章目录功能。
- 框架、依赖版本、正式域名、DNS 或 Netlify 账户设置。

## 8. 兼容性、搜索与公开资料边界

### 8.1 SEO 与语言

- `/` 输出 `lang="en"` 与英文标题、description、分享文案；中文简介保持 `zh-CN`。
- 两版简介的语言关联更新为英文 `/`、中文 `/cn/about`，默认版本指向 `/`。
- canonical 指向各自正式地址；旧英文地址不再作为独立正文进入 Sitemap 或搜索。
- 更新首页及简介的描述，去掉当前暂不提供的项目展示、技能和简历下载承诺。
- 不让根首页的英文选择改变文章、分类、标签和博客的中文元信息。

### 8.2 Pagefind 与 RSS

- 目前简介正文使用 `data-pagefind-body`，但根首页原先作为入口页未承担同样角色；迁移后需要显式检查搜索索引结果。
- 根首页与中文简介可各索引一次简介正文；导航、博客入口重复文案和留白模块不作为独立搜索内容。
- 重定向页与 CV 打印页不进入搜索索引；旧英文简介不产生重复命中。
- 保留既有文章 RSS 的用途，检查构建产物中的 RSS 链接，不因为首页身份变化而让订阅入口指向不存在的地址。

### 8.3 “不展示”与“停止公开”不是同一件事

本方案默认只暂停个人简介中的项目、技能、下载与联系展示，不把该要求扩大为删除原始资料或撤销所有既有公开资源。

- 首屏、导航、页脚、正文、隐藏可访问内容及元信息中，都不应残留简介的邮箱和下载按钮；不能仅用 CSS 把它们藏起来。
- 现有 `static/cv/` PDF 和 CV 打印页若保留，知道原地址的人仍可直接访问。实施验收时必须明确记录这一点，不能宣称“简历已经下线”。
- 若用户希望简历也停止公开，需单独确认：先确定可恢复的私有备份位置，再停止相应静态文件和打印页面输出，并验证线上旧地址。本文不授权直接删除原始 PDF。
- 公开仓库已有的个人资料及 Git 历史不因页面隐藏而变成私有。本轮不重写 Git 历史，不清理无关资料。

## 9. 后续实施顺序与验证

### 第一步：入口与语言迁移

验证：中英文简介均无项目条目、技能列表、CV 下载、邮箱或 `mailto:`；有效经历与教育仍在；所有可点击元素均有有效目标。

复用公共视觉变量，调整简介背景、玻璃面板、按钮、导航和留白间距；只处理与本方案相关的规则。

验证：个人简介、博客首页与文章页在颜色、材质和交互上连续；博客仍有宽敞的双列卡片区域；长文不因简介改版变窄或变透明。

### 第四步：回归与文档

更新针对旧设计的测试，运行完整测试与生产构建，完成桌面和移动端检查后再更新 README。
